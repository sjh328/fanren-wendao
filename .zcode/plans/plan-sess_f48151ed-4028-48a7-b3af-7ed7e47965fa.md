# 剧情 v15「问道录」—— 主线演出化重构（剩余实施步骤）

背景：已在 game.js 中加入 StorySys 演出引擎（卷轴旁白/人物对话/抉择/结算，全屏剧情弹层）、动作注册（story-next/story-choice/story-close/quest-review 等）与 CSS。以下为剩余工作。

## 1. Story 播放队列修复
`Story.play()` 当前在播放中收到新脚本时会丢弃（只合并回调）。改为**队列**：`q[]`，play() 入队，finish() 自动出队播放下一段——支持"章末剧情 → 下一章开篇"连续播放。
另：AutoCult 挂机与战斗快捷键在剧情播放时应挂起（run 循环与 keydown 增加 `Story.active()` 判断，剧情播放中自动修炼暂停等待）。

## 2. GameData.STORIES：九章剧情全面扩写（核心工作量）
新增 `GameData.STORIES`，每章三段脚本（共 27 段，沿用现有血河宗残玉主线设定并大幅扩写）：
- `c1_open … c9_open` 开篇卷轴：基于现有 story 文本扩写为 4~6 场（旁白 + NPC 对话——采药老人遗言/沈青崖/顾轻语/黑袍人"玄影客"/云无月/宗主等）
- `c1_mid … c9_mid` 中段插章：本章第一个目标完成时触发的一段对话/事件场景（遭遇、线索、转折）
- `c1_end … c9_end` 章末剧情：2~4 场对话/旁白 + **抉择**（2~3 选项，不同小额奖励：灵石/感悟/气运，记录入因果）+ 结算场（展示章末奖励）

## 3. QuestSys 接线
- `showStory(idx)` 改为 `Story.play(STORIES['cX_open'])`（新档第一章沿用）
- `check()`：章节完成时不再 storyLog 结尾，改为播放 `cX_end`（结算场展示原 reward），结束后自动衔接下一章 `open`；境界领先自动追认（supR）的章节跳过演出只发奖，避免中期入坑连播轰炸
- **中段触发**：当前章第一个目标完成且未播过时，标记 `p.story.mid[chId]` 并播放 `cX_mid`
- 每条 step 增加 `prog(p)`（返回如 `3/5`）供界面显示进度（27 条目标逐条补）

## 4. 问道页重构（renderTab）
- 顶部**九章进度轨**：已完成✓ / 进行中 / 未启的章节节点条 + 当前章名
- 当前章目标卡：每条目标显示进度（3/5）+ 独立「前往」直达按钮（复用 GO 表）
- 「问道录」按钮 → 剧情回顾弹窗（已看过的开篇/中段/章末列表，可重读；记录章节抉择所选项）
- 支线奇遇录保留下方

## 5. 兼容与收尾
- PlayerFactory：`create()` 增加 `story: { seen:{}, mid:{}, choices:{} }`；`migrate()` 清洗补齐（老档无损）
- `Game.newGame` 播放开篇改走 Story
- verify-v7 新增 6 项测试：新档播开篇 / 中段触发 / 完章播章末+衔接下章 / 进度显示 / 问道录重读 / 老档迁移；跑 v6+v7 全量回归
- UPDATE_NOTES.md 增加 v15 章节

实施顺序：队列修复 → STORIES 文本（分 3 批：c1-c3 / c4-c6 / c7-c9）→ QuestSys 接线 → 问道页 → 迁移与测试 → 文档与验收截图。
